# Leggio: design

Status: draft for review, 2026-10-08
Working name: **Leggio** (Italian for "lectern", the stand that holds a book open). Pending a trademark check, see section 12.

## 1. Summary

Leggio is a free, open-source e-book reader and converter that runs in the browser as an installable Progressive Web App (PWA). It opens EPUB files, keeps your place, and converts between EPUB, .docx, Markdown, plain text, HTML and PDF (print). Everything happens on the user's device: there is no server, no account, no analytics, and no request to any third party.

It is a clean-room implementation built only from public specifications (W3C EPUB 3.3, ECMA-376) and permissively licensed libraries. It is not affiliated with any e-book vendor.

## 2. Goals and non-goals

Goals
- Real users can open a link and read an EPUB within seconds, on desktop or phone, with nothing to install.
- Conversions that people actually search for: EPUB to .docx, EPUB to PDF, .docx to EPUB, Markdown/text to EPUB, EPUB to text/Markdown/HTML.
- Privacy that can be checked, not just promised: no user data ever leaves the device.
- A codebase small and clear enough for one maintainer and for outside contributors.

Non-goals (v1.0)
- PDF import or PDF to EPUB.
- Legacy .doc (Word 97-2003), MOBI/AZW, FB2.
- DRM removal of any kind. Protected books are detected and refused with an explanation.
- Highlights, notes, full-text search, sync, text-to-speech, fixed-layout rendering.
- Translations of the UI (English only; browsers translate on demand).

## 3. Principles

1. **Local only.** All parsing, rendering, conversion and storage happen in the browser. Nothing is uploaded.
2. **Simple over complete.** Where a full spec feature costs a lot and helps few readers, we take the simple path and document the limit (see section 6).
3. **Clean room.** Implementation is written from public specifications. We do not read the source of other e-book readers or converters (for example Calibre or Foliate) while building the matching feature. Sources are listed in `CLEANROOM.md`.
4. **One shape for every book.** Every input format becomes the same internal model; every output starts from it.

## 4. Scope

### v1.0
1. **Library.** Import `.epub` by file picker or drag and drop. Shelf with cover, title, author. Delete a book.
2. **Reader.** Paginated view. Next/previous by arrow keys, tap or click on page edges, swipe on touch screens. Table of contents. Progress percentage. Reopens at the last position.
3. **Comfort.** Font size, three themes (light, dark, sepia), bookmarks.
4. **Convert.**
   - In: EPUB, .docx, Markdown, plain text.
   - Out: EPUB, .docx, Markdown, plain text, single-file HTML, PDF via a print-ready view and the browser's "Save as PDF".
   - Text and Markdown to EPUB ask for title and author.
5. **PWA.** Installable, works offline after the first visit.
6. **Safety.** Book content is sanitized and shown in a sandboxed frame with scripts disabled.
7. **DRM.** Protected books are detected and the user sees a clear message.
8. **Privacy page** in the app and `PRIVACY.md` in the repo. "Delete all data" button.

### Roadmap (after v1.0)
Highlights and notes with export; search inside a book; FB2 import; fixed-layout EPUB; optional NCX output for very old devices.

## 5. Architecture

```
 .epub ─┐                     ┌─> .epub
 .docx ─┼─>  Book (model)  ───┼─> .docx
 .md   ─┤                     ├─> .md / .txt / .html
 .txt  ─┘                     └─> PDF (print view of the .html output)
```

### Internal model (`src/core/model/book.ts`)
```ts
interface Book {
  meta: { title: string; authors: string[]; language: string; identifier: string };
  chapters: Chapter[];          // reading order
  toc: TocEntry[];              // nested, points at chapter + optional fragment
  resources: Map<string, Resource>; // images, fonts, stylesheets, keyed by normalized path
  cover?: string;               // key into resources
}
interface Chapter { id: string; title?: string; html: string } // sanitized XHTML body
```

### Units
| Unit | Responsibility | Depends on |
|---|---|---|
| `core/epub/read.ts` | Open zip, read `META-INF/container.xml`, the OPF package (metadata, manifest, spine), the nav document (EPUB 3) or NCX (EPUB 2), the cover. Produce a `Book`. | fflate, `core/sanitize` |
| `core/epub/write.ts` | `Book` to a valid EPUB 3.3: `mimetype` first and stored uncompressed, container, OPF with `dc:identifier` and `dcterms:modified`, nav document, XHTML chapters. | fflate |
| `core/epub/drm.ts` | Decide whether a book is protected (rules in 6.4). | none |
| `core/convert/from-*.ts` | docx, md, txt to `Book`. | mammoth, marked |
| `core/convert/to-*.ts` | `Book` to docx, md, txt, html. | fflate, turndown |
| `core/sanitize.ts` | Remove scripts, event handlers, `javascript:` URLs, forms, external resource references. | DOMPurify |
| `reader/paginator.ts` | Render one chapter in a sandboxed iframe, split it into pages with CSS columns, turn pages, report position. | browser DOM |
| `reader/location.ts` | Convert between a position and a page; restore after font-size or window changes. | none |
| `storage/db.ts` | IndexedDB access (schema in 6.6). | idb |
| `ui/` | Svelte screens: Library, Reader, Convert, Settings, Privacy. Simple view state, hash URLs so the back button works. | Svelte |

`core/` has no UI code and runs in tests without a browser window (DOM provided by happy-dom).

## 6. Key decisions (where we keep it simple)

### 6.1 Position in a book
A position is `{ spineIndex, fraction }`: which chapter, and how far into it (0 to 1). We do not implement full EPUB CFI. This survives font-size and window changes well enough for reading, and bookmarks store the same pair plus a short text snippet.

### 6.2 Pagination
One chapter at a time is loaded into the iframe through `srcdoc`. Reader CSS sets the column width to the frame width, so the browser lays out pages; turning a page moves by one column. Images and stylesheets inside the book are rewritten to `blob:` URLs created from the zip entries. Links to other chapters are intercepted by the parent page; external links open in a new tab with `rel="noopener noreferrer"`.

### 6.3 Isolation and Content-Security-Policy
- The iframe uses `sandbox="allow-same-origin"` without `allow-scripts`, so book scripts never run while the parent can still measure the layout.
- A CSP `<meta>` tag (GitHub Pages cannot set headers) restricts the app to its own origin: `default-src 'self'; img-src 'self' blob: data:; font-src 'self' blob: data:; style-src 'self' 'unsafe-inline'; connect-src 'self'; frame-src 'self' blob:; object-src 'none'; base-uri 'self'; form-action 'none'`. `srcdoc` frames inherit it, so a book cannot load anything from the network either.
- Sanitizing (DOMPurify) is a second barrier, not the only one.

### 6.4 DRM detection
A book is treated as protected if any of these holds:
- `META-INF/encryption.xml` lists an encrypted resource whose algorithm is not one of the two font-obfuscation algorithms (`http://www.idpf.org/2008/embedding`, `http://ns.adobe.com/pdf/enc#RC`);
- `META-INF/rights.xml` exists (Adobe ADEPT);
- `META-INF/sinf.xml` exists (Apple FairPlay).
Font obfuscation alone is not DRM: those books open, with the obfuscated fonts ignored.

### 6.5 PDF and .docx output
- **PDF** reuses the single-file HTML output with a print stylesheet (page size, margins, chapter page breaks) and calls `window.print()`. No PDF library.
- **.docx** is written by our own small writer: headings 1-3, paragraphs, bold, italic, lists, images, a page break per chapter. Tables are flattened to text rows (documented limit).

### 6.6 Storage
IndexedDB, database `leggio`, version 1:
- `books`: `{ id (SHA-256 of the file), title, authors, coverBlob, fileBlob, addedAt }`
- `progress`: `{ bookId, spineIndex, fraction, updatedAt }`
- `bookmarks`: `{ id, bookId, spineIndex, fraction, snippet, createdAt }`
- `settings`: `{ key, value }`
On first import the app calls `navigator.storage.persist()` so the browser does not evict the library. "Delete all data" deletes the database and the service-worker caches.

### 6.7 Errors
`core/` throws typed errors: `NotAnEpubError`, `DrmProtectedError`, `MalformedBookError`, `UnsupportedFormatError` (for example `.doc`). Readers are lenient where possible: no nav and no NCX means a TOC built from chapter headings; XHTML that fails XML parsing is retried with the HTML parser. Fixed-layout books open with a warning that they may look wrong. The UI turns every error into a short plain-English message; one bad book never breaks the library. Storage-quota errors explain how much space is needed.

## 8. Testing

### Fixtures
- **Generated** (`scripts/make-fixtures.ts`, output released as CC0): EPUB 2 with NCX, EPUB 3 with nav, no TOC, file names with spaces, accents and percent-encoding, nested folders, missing cover, font obfuscation (must open), fake DRM via `encryption.xml`, `rights.xml` and `sinf.xml` (must be refused), malicious content (`<script>`, `onerror`, `javascript:` links, external images and fonts), fixed layout, broken XHTML. Small .docx files built from hand-written XML: headings, lists, bold/italic, images, a table.
- **Real corpus**: about 20 Standard Ebooks titles plus about 5 Project Gutenberg EPUBs (the most common real-world quirks). Pinned URL and SHA-256 in `tests/corpus.json`, downloaded by `scripts/fetch-corpus.ts`, cached in CI, never committed. Licensing of each source is checked before the list is fixed.

### Levels
- **Unit (Vitest)** on `core/`: each reader and writer; round trips (Markdown to EPUB to Markdown keeps text and headings); DRM rules; sanitizer against every malicious fixture.
- **Corpus test**: every corpus book opens with title, author, a non-empty TOC and all spine chapters parsed, and no error.
- **EPUBCheck (CI)**: every EPUB our writer produces from the fixtures passes with zero errors.
- **End to end (Playwright, Chromium and WebKit)**: import a book, turn pages, reload and land on the same page, add a bookmark, convert and download each format, work offline after the first load, a 375 px phone viewport, **zero requests to any origin other than the app's own** (network listener), no serious or critical accessibility violations (axe).

### Success criteria for v1.0
All of the above pass in CI on `main`. These numbers are what we will report in the README, measured, not estimated.

## 10. Delivery

- **License: MIT.** Shortest and most widely understood permissive license; all runtime dependencies are compatible. (Apache-2.0 would add an explicit patent grant, which matters little for a reader with no patented techniques.)
- **README (English):** what it is, live link, screenshots, features, supported conversions and their limits, privacy summary, how to run locally, how to contribute, roadmap, the clean-room note, and a clear statement that Leggio is not affiliated with or endorsed by Amazon, Apple, Adobe, Microsoft, Kobo or any other company, and that it does not remove DRM.
- **PRIVACY.md and in-app page:** what is stored (only on the device), what is never collected, how to delete it, and the honest note that GitHub Pages, as host, may log technical access data such as IP addresses under GitHub's own privacy statement, which we link.
- **CLEANROOM.md:** the rules and the list of specifications used (W3C EPUB 3.3, EPUB Reading Systems 3.3, ECMA-376 Part 1, CommonMark, MDN).
- **DEVLOG.md:** short dated entries on how the project was built with AI assistance: decisions, what the AI got wrong and how it was caught, what was verified and how. Written for a portfolio reader.
- **Design:** original name, logo and colors. UI concepts (shelf, page edges, TOC drawer) are generic to e-readers; no third-party icons, artwork or wording.
- **Hosting:** GitHub Pages via a GitHub Actions workflow. Creating the GitHub repository and every push happen only with the owner's explicit OK.
